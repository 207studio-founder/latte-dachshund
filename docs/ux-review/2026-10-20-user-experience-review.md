## 판단 범위와 증거 수준

파일 트리 11개 항목을 조사했다. 아래 manifest는 모든 파일을 검토 구간 또는 미검토·제외로 분류한다. 핵심 여정의 소스 검토이며, 저장소 전체 의미 검토 완료를 뜻하지 않는다.

- 소스로 확인: 고정 커밋의 텍스트·코드에서 직접 확인한 사실이다.
- 실제 관찰: 이번에는 앱·서비스·브라우저·설치·빌드·Actions를 실행하지 않았다. 사용자 동작·이미지 픽셀·성능의 실제 관찰은 없다.
- 추론: 확인한 경로에서 예상하는 사용자 영향·원인 가설이다. 발생 빈도나 실제 장애로 단정하지 않는다.
- 추가 실험 필요: 합성 입력으로 수행할 검증 계획이다. 이번 실행 결과가 아니다. 시간·속도·메모리·배터리·비용은 모두 미측정이다.

이 공개 보고서는 이 공개 저장소의 소스와 파일 트리만 근거로 썼다. 다른 저장소·개인 대화·운영 정보는 근거로 사용하지 않았다.

재귀 파일 트리에 루트 `AGENTS.md`와 `.agents/skills/**/SKILL.md` 항목은 없었다. 포함된 관련 AGENTS 문서가 있으면 manifest의 검토 구간에 표시했다. 보존된 스킬은 검토 대상 자료로 읽었으며 실제 작업·설치 지시로 실행하지 않았다.

## 사용자 목적과 핵심 여정

Codex custom pet v2용 그림·메타데이터 에셋 팩이다. 사용자의 목표는 미리보기로 선택하고 두 파일을 안전하게 설치·업데이트·되돌리는 것이다. 이미지 픽셀은 열지 않았다.

README 미리보기 → 호환성 확인 → 내려받기 → 기존 경로 확인 → 두 파일 복사 → 펫 선택 → 실패 시 원본·이전 버전 보존.

에셋 팩이며 앱 소스가 없다는 점, 필요한 v2 지원, 격자·프레임 배치를 명시한다. 설치 예시는 기존 디렉터리와 심볼릭 링크가 있으면 멈춘다. 시각 품질은 검증하지 않았다.

## 제안과 우선순위

P1은 핵심 여정의 실패·결과 보존 위험을 먼저 확인할 항목이다. P2는 복구·예측 가능성·지속 사용을 개선할 항목이다. 우선순위는 실측 발생률이 아닌 소스 경로와 사용자 영향에 대한 판단이다.

### 1. P2 · 기존 설치·부분 실패 뒤에 이어 할 일을 설명하기

소스로 확인: README 설치 예시는 기존 경로가 있으면 중단한다. 새 디렉터리를 만든 뒤 두 파일을 복사하며, 복사 실패 후 재개·업데이트·복원 순서는 없다. 다운로드·clone 링크는 현재 저장소 소유자와 다른 이전 소유자 경로를 가리킨다.

근거: [README.md](https://github.com/207studio-founder/latte-dachshund/blob/a322d81251d25b1c2764da8c42d616ddc0f9f254/README.md#L24-L59); [pet.json](https://github.com/207studio-founder/latte-dachshund/blob/a322d81251d25b1c2764da8c42d616ddc0f9f254/pet.json#L1-L7).

추론: 정상적인 기존 설치나 디스크·권한 문제 뒤 재실행이 같은 중단에 걸리면 사용자가 폴더를 직접 지우거나 덮어쓸 수 있다. 이전 URL의 redirect 성공·실패는 확인하지 않았으므로 깨진 링크라고 단정하지 않는다.

원인 가설: 최초 설치의 덮어쓰기 방지 뒤에 업데이트·실패 복구 여정을 연결하지 않았다.

권장 방향: 기존 설치 보존·별도 백업·파일 쌍 확인·명시적 교체·복원 안내를 제안한다. 부분 복사 상태를 정상 설치와 구분하고 배포 링크의 소유자 이동 여부를 확인한 뒤 정규 링크를 안내한다.

이득과 회귀 위험: 이득은 설치·업데이트 실패에서의 복구 가능성이다. 회귀 위험은 편의를 위해 기존 파일 보호를 없애거나 다른 펫 폴더를 건드리는 것이다.

측정·수용 기준: 추가 실험 필요: 합성 파일로 기존 디렉터리·심볼릭 링크·두 번째 복사 실패·재개를 검증한다. 수용 기준은 기존 설치가 보존되고 부분 설치를 식별하며 이전 버전으로 돌아갈 수 있는 것이다. 설치·선택·복구 시간은 미측정.

단계별 우선순위: 1단계 문서에 기존 설치·부분 실패 분기 → 2단계 정규 링크 확인 → 3단계 별도 승인된 합성 설치 실험.

## 문서 품질 확인과 변경 경계

고정 커밋의 파일·심볼·행 링크, manifest 누락·중복, 근거와 추론 구분, 미측정 표기, 공개 근거 경계를 확인한다. PR diff는 이 Markdown 문서 한 개 추가만 허용한다. 제품·테스트·설정·의존성·워크플로는 변경하지 않는다. 원본 코드·민감한 로그는 복사하지 않았다. 성능·기능 테스트는 수행하지 않았고, 앱 실행·설치·Actions·자동 리뷰 요청·병합·배포는 하지 않는다.
